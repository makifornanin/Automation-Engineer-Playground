# AEP Lab Standard

Every Automation Engineer Playground lab must follow the same learning philosophy.

## Core Learning Rule

Before building, the learner should understand:

1. What is this?
2. What problem does it solve?
3. How can this help a real business?

AEP should teach understanding before implementation.

---

## Standard Learning Flow

Every lab follows:

```text
Understand
↓
Business Problem
↓
Architecture
↓
Guided Build
↓
Successful Test
↓
Break It
↓
Debug It
↓
Challenge
↓
Verify
↓
What You Learned
```

---

## Guided Build Rules

Every guided build should:

- explain the workflow before building
- build one logical step at a time
- use clear node/component names
- explain important field mappings
- explain JavaScript when used
- avoid unnecessary complexity

For important workflow components, explain:

### What

What does this component do?

### Purpose

Why is this component needed?

### Business Reason

Why would a real business need this behavior?

---

## Testing Rules

Every lab must include:

- one successful test
- one intentional failure scenario
- one debugging exercise

The learner should compare:

```text
Input
↓
Expected Result
↓
Actual Result
```

---

## Make It Your Own Rule

After the challenge, learners should be encouraged to modify the workflow and create their own variation.

This may include:

- changing the business scenario
- creating new sample data
- modifying fields
- changing logic
- creating a new failure scenario

The goal is independent experimentation, not copying.
