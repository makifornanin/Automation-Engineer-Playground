# Kaz V2 — Implementation Plan

Design: `docs/superpowers/specs/2026-09-18-kaz-v2-design.md`
Baseline: `v1.1.0`

Order is chosen so each step is testable on its own and nothing privileged is
reachable before its guard exists.

## 1. Database

`database/aep_web_kaz_schema.sql` (idempotent, same six-step rule as the
existing schema): `aep_web_kaz_threads`, `aep_web_kaz_messages`, RLS on and
forced, revoke from anon/authenticated, minimal grants, owner-scoped policies
on `(select auth.uid())`, no admin policy. Applied through the established
project workflow (SQL editor), like the other four tables.

## 2. Server foundation (server-only, not browser-reachable)

- `web/src/lib/kaz/threads.ts` — read/append messages, read/raise/reset help
  level, bounded history. Owner-scoped through the learner's own session.
- `web/src/lib/kaz/help-ladder.ts` — pure: current level, escalation from the
  message text, reset on evidence advance.
- `web/src/lib/kaz/intent.ts` — pure: does this question need the workflow, the
  execution, both, or neither.
- `web/src/lib/kaz/context.ts` — deterministic retrieval: current chunk, lab
  outline, progress/evidence, canonical summary gated by help level.
- `web/src/lib/kaz/canonical.ts` — read `labs/NN-*/workflow/*.json`, strip
  credentials, summarise (level 3) or include node configuration (level 4).
- `web/src/lib/kaz/gateway-client.ts` — the only caller of the Gateway; reads
  `KAZ_GATEWAY_URL` / `KAZ_GATEWAY_SECRET`; timeout, size cap, honest errors.
- `web/src/lib/kaz/throttle.ts` — per-learner interval and per-minute cap.

## 3. Server Action

`web/src/lib/kaz/kaz-actions.ts` (`"use server"`): `askKaz(prevState, formData)`.
Validates the lab and chunk against real content, requires a session, requires
hands-on access for the lab, throttles, loads the thread, decides intent and
help level, assembles context, calls the Gateway, appends both messages,
returns a typed state. Every privileged read stays behind `server-only`.

## 4. Kaz Gateway (n8n)

One workflow, built through the n8n API and exported to
`docs/kaz/aep-kaz-gateway.json` with no secret in it:

Webhook (Header Auth credential) → validate request → decide what to fetch →
n8n node: workflow list/get by webhook path → n8n node: latest execution →
sanitize (Code) → build prompt (Code) → Gemini → Respond to Webhook.

Uses the existing read-only n8n API credential and the existing Gemini
credential.

## 5. UI

- `web/src/components/kaz/KazPanel.tsx` — the panel: thread, input, context
  label, honest visibility line, loading state.
- `web/src/components/kaz/KazLauncher.tsx` — the floating orb button, proactive
  pulse, open/close state; mounted from the lab and Capstone pages so it knows
  the lab and chunk.
- Remove `/kaz` page and its dock item; redirect `/kaz` to `/labs`.
- Keep `KazHints` and Home's note as they are.

## 6. Tests

Unit: help ladder and its reset; intent heuristics; canonical gating by level
(level 1–2 must contain no canonical configuration); sanitization rules (each
forbidden field individually); throttle; thread-per-lab including Capstone;
message length cap; action refuses an unknown lab, an unknown chunk, a locked
lab and an anonymous caller; the browser cannot select a workflow it does not
own; gateway client never sends the secret to the client bundle (security
invariants scan); `/kaz` redirect; panel rendering states.

## 7. Live E2E

The 21 checks in the directive, against real n8n and real Gemini, with two
learners for the isolation checks.

## 8. Verify and close

`npm run verify`, secret scan against the real configured secrets, update
`ROADMAP.md` and write `docs/qa/AEP-KAZ-V2.md`, commit in focused commits, do
not push.
